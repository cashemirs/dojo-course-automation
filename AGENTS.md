# Правила работы в проекте

## Общение и обучение

- Отвечай на русском, коротко и понятным для начинающего языком.
- Объясняй причину ошибки и показывай конкретное исправление.
- Если пользователь спрашивает, как работает код, сначала объясняй; изменяй файлы,только когда он просит это сделать.
- Перед изменениями читай актуальное содержимое файлов и сохраняй изменения пользователя.
- Не расширяй задачу: избегай лишних рефакторингов и изменений других тестов.

## Playwright и TypeScript

- Используй Playwright Test и TypeScript.
- Предпочитай getByRole, getByLabel и getByTestId, если они подходят реальной разметке.
- Не придумывай подписи, test ID, URL и сообщения об ошибках: проверяй их по доступному коду, DOM или результатам запуска.
- Уточняй область поиска локатора вместо использования first() или last() для случайного обхода нескольких совпадений.
- Используй ожидающие проверки await expect(locator), а не фиксированные паузы.
- Делай тесты независимыми: каждый тест готовит необходимые данные и не зависит от порядка запуска.
- Генерируй уникальные данные внутри теста или его фикстуры.
- Негативные тесты должны проверять конкретную ожидаемую причину ошибки, когда текст или другой стабильный сигнал известен.
- Не оставляй test.only и test.describe.only в готовых изменениях.
- Сохраняй forbidOnly для CI в конфигурации.

## Проверка и Git

- Запускай проверки, соответствующие изменению; при простом перемещении кода достаточно проверить обнаружение тестов.
- Не утверждай, что тесты прошли, если они не запускались. Сообщай об ограничениях проверки.
- Не добавляй в Git node_modules, отчёты, результаты тестов, секреты и сохранённые данные авторизации.
- Делай commit, push и создавай pull request только по прямой просьбе пользователя.
